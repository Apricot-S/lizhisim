# 再設計の判断待ち一覧

全項目の状態は **unresolved question / 未決**。以下の選択肢は **candidate design** であり、先頭を採用案とする意味はない。今回の文書作成を終えるために即時回答を要求する一覧ではなく、人間が設計をレビューし、実装開始前に必要な判断を選べるようにする。

## 採用へ進むときの文書手順

1. ownerの判断と根拠を、この一覧の該当IDへ記録する。
2. 採用した契約を要求仕様・新設計の規範へ移し、影響する旧ADRを後継ADRでsupersedeする。旧本文・cycle logを新判断へ書き換えない。
3. 用語が必要になった時点で用語集の規範に従う。未決の麻雀語を造語しない。
4. 実装開始が明示された後、採用範囲のtest listを作り、一項目ずつTDDを行う。今回の案の存在だけでは開始しない。
