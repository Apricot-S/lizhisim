## 4. Candidate design: API を決める前に残す契約

1. **Agent の判断は打牌と鳴きだけに限定しない。** 流局時の申告や、採用ルールで必要になる進行上の選択を扱える意味上の入口を比較する。今の段階で一つの巨大 action enum や trait method に固定しない。
2. **Agent と engine の判断を分ける。** LizhiSim が複数卓の互換な要求を集約し、Agent は選択とバッチ推論・通信、非同期回答を担当する。合法性、和了者の採用、資格更新、局・対局の終了、精算は engine のルール意味論で判断する。
3. **対局開始条件は通常の東1局・同一開始点だけに限定しない案を比較する。** 新決勝方式には持越し点や異なる進行があり、参加者と固定座席 index の対応を分ける必要がある。
4. **局終了と意思決定終了を同一視しない。** 最終打牌の反応、聴牌申告、公開、局精算、対局進行が残り得る。すべての対局の完了を待って返す C の契約でも、内部の判断段階は分けられる。
5. **完全情報の保持と Agent への公開は別にする。** engine が聴牌を計算できても、他家の未公開手牌を観測へ渡したり、申告前に漏らしたりしない。
6. **通常ルール・対局形式・大会持越し/裁定・実行予算を分ける。** 新決勝方式を単なる順位点の設定に押し込めず、かといって大会運営全体を卓内 API に必須化しない。
7. **異なる ruleset の混在と Agent 共有の契約を次段階で確認する。** Agent に渡す rule 文脈、観測・行為の意味版、推論互換性が必要。複数卓が同一 Agent を使うときの要求供給・待機・batch の粒度は未決。

これらは構造上の提案であり、確認事実から唯一の Rust 型構成や実装方式が決まるという主張ではない。

| 実卓の反則・裁定 | 第5問で再現しない方針が確定 | 通常 simulation は合法行為のみ。公式条項は対象外として追跡。API エラーの後処理は Q-09 で決める |

| 終局と申告 | 第6問で選択の扱いが確定。公開順の確認済み差分と未確認対象は6節 | API 契約と受入例を決める前に未確認条項を深掘りする |

今回の調査は、全対象を verified にする工程ではない。構造差が見つかったので、API を最初の一ルールだけに合わせて確定する手順を変更する。次に採否が必要な意味上の契約を一つずつ質問し、その実装項目を選ぶ段階で公式の詳細値・corner case と独立した期待結果を確定する。

## 6. 流局時の聴牌申告・公開順（2026-11-18追加調査）

### Confirmed requirement と確認事実の区別

第6問で、聴牌伏せを認めるルールでは実際に聴牌している者の合法な選択肢とし、認めないルールでは選択肢を出さないことが確定した。天鳳・雀魂を選択肢なしとすることはユーザー指定であり、今回その公式条項を新しく確認できたと読み替えない。

**「立直者が公開しなければならない」と「立直者が先に公開する」は異なる規則。** 公式本文には立直者先行の方式と、立直に関係なく席順で申告する方式がある。立直者先行を全ルール共通の処理には固定しない。

### 分離するルール判断

| 判断 | 意味・確定した境界 |
|---|---|
| 聴牌判定 | 牌姿・副露・当該ルールから実際の聴牌を判定する |
| 聴牌伏せの許可 | 実際に聴牌している者が不聴申告を選べるかをルールで決める |
| 強制公開・申告 | 立直等によって選択不能かを別に決める。強制処理のためだけの Agent 選択肢は出さない |
| 優先グループ | 立直者を先行させるか。公開義務だけを理由に先行させない |
| グループ内・残りの順序 | 現在親/起家等の起点、席順、対象座席を決める |
| 公開情報の更新 | 先行する公開・不聴申告を反映してから、次の選択に使う観測を作る |
| 精算・連荘 | 実際の聴牌と申告を区別し、ルールに従う精算上の資格を確定してから判断する |

### Candidate design: 意思決定と記録への反映

```text
最終打牌の和了反応を解決
  -> 終局種別に応じて流局の申告・公開へ
  -> ルールで公開義務と順序を決める
  -> 強制処理、または選択可能な聴牌者だけへ Agent 要求
  -> 公開情報を更新し、次の座席へ
  -> 全員の扱いを確定
  -> 局結果・聴牌料・連荘・対局終了の判断へ
```

これは内部表現の候補であり、Rust 型や method signature は決めない。公開順が将来の Agent の観測へ影響する以上、全員の申告を同じ観測で同時収集する方式とは意味が異なる。別卓の要求を batch 化することと、同一局の公開順を省略することは区別する。

検証候補は、非立直・実聴牌・伏せ可のときだけ二つの意味上の選択肢があること、伏せ不可/強制公開/実不聴では選択要求がないこと、複数立直者の優先グループと残りの席順、現在親と起家が異なる場合、先行する公開だけが後続観測へ入ること、同じ申告列で配送順や batch 分割を変えても結果が一致することである。

公開・不聴申告・Agent の選択・強制処理・実際の聴牌は、再生上の意味を区別する案とする。立直者間を同時公開にするか順次公開にするかも、明示された規則に従い、便宜的な同時化を既定値にしない。未確認の団体・サービスの順序は未解決のまま残す。
