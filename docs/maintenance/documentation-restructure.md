# 文書再構成の記録

## 再構成の根拠と確認

2026-09-15に[OpenAI公式記事](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)を確認した。記事の、作業に応じた文書参照、承認境界の明確化、完了範囲の明示という助言を、このリポジトリに適用した。

| 従来の指示 | 再構成後 |
|---|---|
| 変更前に固定順で文書を読む | AGENTS.mdの表から、対象文書と関連ADRを読む |
| AGENTS.mdと開発手順書にTDD詳細が重複 | AGENTS.mdに必須条件、開発手順書に詳細と例を置く |
| 検証方針とCI運用を重複して記載 | 開発手順書の5・12節を規範とし、必須コマンドはAGENTS.mdにも残す |
| 依頼の完了範囲が暗黙 | タスクごとに成果物と終了位置を指定する |
| 通常作業を進めてよい境界が暗黙 | 調査・編集・検証・今回の失敗修正の続行を明記する |

製品方針、Rust規約、ピンインの決定手順、公式情報の証跡、牌譜の取得・保存境界、TDDの順序とtest削除条件は維持した。設計判断の意味は変更していないため、Accepted ADRは変更していない。

リポジトリ内に独立した既存プロンプトファイルは見つからなかったため、[タスクプロンプト](../task-prompts.md)に依頼例を追加した。アプリや個人設定の指示は変更対象に含めていない。モデル固有のプロンプトガイドはWeb取得できず、補助資料としてOpenAI Docsスキル同梱のprompting guideを参照した。

### 次回の実作業で確認すること

文書の静的確認と、モデルが実作業で規約を守るかの評価は別である。次の代表タスクで、不要な読込・承認待ち・検証の反復と、重要な制約の見落としがないか確認する。問題が再現した場合に、その判断境界だけを修正する。

| タスク | 期待する結果 |
|---|---|
| 文書の誤字修正 | 対象と参照元を確認し、Rust検証を実行せず文書の完了条件を満たす |
| 一つの実装項目 | 意図したredからgreen・refactor・必須検証・cycle log更新まで進む |
| 三角測量が必要な項目 | 次の一項目で別サイクルを回し、独立した契約を失うtest削除をしない |
| 未決の麻雀識別子 | 用語集の空欄を追加してユーザー判断を求め、production名を造語しない |
| 公式値の証跡不足 | 推測でverifiedにせず、draftまたはblockedとして根拠を記録する |
| 製品方針を変える設計案 | 明示的合意と後継ADRが必要な点を示す |

この実作業評価は未実施であり、モデル間の品質や速度の改善を測定したものではない。

## docs全体の再構成（2026-09-15）

[文書案内](../README.md)を入口にし、作業手順・設計・要求・証跡・履歴の参照先を整理した。

| 対象 | 変更と維持した情報 |
|---|---|
| 開発手順書 | 入口と共通規約を残し、旧3・4・9節をTDD、5・6節をテスト戦略、7・8節を外部crateとプリセット、10・11節をレビュー、12・13節を検証へ移設。節番号と手順の契約を維持 |
| 初回実装gate | 開発手順書の旧2節をPhase 0 reviewへ移設。既に開始したPhase 1の再承認条件と区別 |
| 設計5文書・要求・用語・出典 | 必要な節へ進むリンクを追加。要求ID・用語・プリセット一覧・出典の確認日を維持 |
| 未決事項 | 要求仕様からロードマップの状態表へ参照を集約 |
| test list | 入口のPhase 0説明とactive扱いを修正。各listのCurrent・項目・cycle logは変更なし |
| ADR | 一覧へ対象別の案内を追加。個別ADR本文は変更なし |
| タスクプロンプト | 依頼例を残し、再構成理由と評価計画を本書へ移設 |

既存規範に合わせた整合修正:

- 出典台帳・ルール設計に残っていた原資料snapshotや画像hashの必須扱いを、ADR-0008のSourceReview方式へ揃えた。公式情報を再調査した変更ではないため、出典確認日は更新していない。
- アーキテクチャのadapter依存方向の説明を、同文書の依存図とfunctional coreの方針に揃えた。domainからadapterへ依存しない。
- 検証コマンドを文書・Rust・dependency auditに分け、探索コマンドと検証を区別した。必須gateは維持した。

設計判断の追加・変更はなく、Accepted ADRのsupersedeは行っていない。モデルの性能比較は行っていない。
