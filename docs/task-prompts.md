# タスクプロンプト

GPT-6 Astra向けの依頼例。`{...}`を今回の対象に置き換え、該当する例だけを使う。[AGENTS.md](../AGENTS.md)の全文を毎回貼り付ける必要はない。

## 依頼に含めること

目的、対象、完了条件、今回固有の制約を伝える。既存文書で決まっている設計やTDD手順は参照に任せる。作業方法を追加指定するのは、今回それが必要な場合だけとする。

以下の例はリポジトリの規約を参照できる環境を前提とする。別の環境で使う場合は、対象ファイルと必要な規約を渡す。

## 実装を進める

```text
{test listのパス}の{対象項目または到達したい振る舞い}を実装してください。
AGENTS.mdと対象文書に従い、必要な項目を一つずつTDDで進めてください。
完了範囲は{一項目／指定した振る舞いまで}です。
範囲内の修正、必須検証、cycle logと関連文書の更新まで続けてください。
```

「一項目」はtest list全体の実装許可ではない。三角測量が必要なら別の一項目として続け、単一例の仮実装を一般化済みと報告しない。複数項目を依頼しても、redは一項目ずつ確認する。

## バグを直す

```text
{再現手順または失敗ログ}で、{実際の結果}になります。
期待する結果は{期待値とその根拠}です。
最小の再現テストでredを確認し、修正と必要な検証・記録更新まで完了してください。
```

## 設計・文書を更新する

```text
{対象文書または設計課題}を、{達成したい状態}へ更新してください。
関連する要求・用語・ADR・リンクの整合性まで確認してください。
今回の成果物は文書です。未決事項は、判断に必要な根拠と選択肢を示してください。
```

## レビューする

```text
{差分または対象ファイル}をレビューしてください。
重点は{正しさ／TDDの契約／責務境界など今回の観点}です。
指摘には具体的な箇所、問題が起きる条件、影響を示してください。
今回は指摘の報告までを完了範囲とします。
```

## 中断した作業を再開する

```text
{test listのパス}のCurrentとcycle log、作業ツリーの差分から再開してください。
完了範囲は{前回合意した範囲}です。
記録済みの結果を使い、未完了の修正・検証・文書更新を進めてください。
```

再構成の背景と評価項目は[再構成の記録](maintenance/documentation-restructure.md)を参照する。
